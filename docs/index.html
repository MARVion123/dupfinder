Prove it first.
Then delete.

A self-hosted tool that finds duplicate and near-duplicate files on your own NAS. Before it offers to delete anything, it compares the files byte for byte. And every deletion can be undone.

§ 01

Six passes, each one paying for the next

Comparing every file with every other file is unaffordable. So each pass throws away what the next one no longer has to look at — and gets more expensive per file precisely because less is left.

The bars show how much of a file each pass reads — as an order of magnitude, not a linear scale. Pass 5 reads twice because it holds two files side by side.

Why pass 5 exists

MD5 is not enough when the answer is "delete"

An MD5 collision is astronomically unlikely — but deletion is irreversible. So the match is proven rather than assumed. Only proven groups carry the mark.

Why pass 6 exists

A rating, not a claim

The fuzzy hash scores content similarity from 0 to 100. That number is blended with the size ratio and filename similarity — content dominates, the rest only tips a borderline pair.

§ 02

Four things standing between you and a lost file

A tool that deletes on request is a tool nobody watches closely enough. So here every step is either proven or reversible.

01 — Proof

Compared byte for byte

Every match is read back in full before it is ever offered. What "identical" means here has been demonstrated.

02 — Reversible

Quarantine, not deletion

By default files move into .dupfinder-trash/scan-N/ and come back with one click from the action log. The DSM recycle bin is an option too.

03 — Floor

The last copy survives

Select every file in a group by accident and one is kept anyway, reported as skipped. A group cannot be emptied.

04 — Rehearsal

Simulate it first

One tick in the action bar runs the whole thing — allowlist check, last-copy protection, destination arithmetic — and stops just short of the filesystem call. Same code path, not a parallel one.

§ 03

What a result looks like

A table where every column sorts: similarity, copies, file size, reclaimable bytes, folders spanned, suggestion confidence. Results appear while the scan is still running.

§ 04

What it finds, and where it stops

Exact duplicates are found in any file type; that comparison is blind to content. For similar files the answer depends on the format. Measured on a revised document: one paragraph rewritten, one added.

FormatSimilarity detectedMethod
CSV, log files99 %Fuzzy hash
PDF with an uncompressed text stream99 %Fuzzy hash
Plain text, Markdown, source code97 %Fuzzy hash
WAV, RAW — trimmed at the end97 %Fuzzy hash
Photo, re-encoded or resized100 %Perceptual hash
Film, different container (remux)foundFuzzy hash
Word, Excel, ODT ZIP containers: one small edit produces a completely different compressed stream 0 %— exact only
Film, re-encoded Two encodings share no bytes at all; that would need a video fingerprint 0 %— exact only

Measured with this tool's own methods. For the formats scoring 0 %, exact detection is unaffected — and that is the part you delete on anyway.

Images

Two methods, one of them wasted

The same photo at two JPEG qualities: the fuzzy hash scores 0 %, the perceptual hash 100 % — at a twenty-fourth of the cost. So images now go through the perceptual hash only.

Cache

The second run is cheap

Hashes are cached on path, size and modification time. A re-scan only pays for what actually changed.

§ 06

Install

Two ways onto a Synology, and choosing between them comes down to a single rule in DSM. Everything else about them is the same.

  Package Center Service
Tile with Start, Stop and Open yes no
Icon in the DSM main menu, draggable to the desktop yes no
Reads your shares after you grant it, per share straight away
Runs as dupfinder, its own user root
Starts with the NAS yes yes

DSM 7 only lets Synology-signed packages run as root. That one rule produces every difference in this table: a package cannot see your shares until you say so, and a plain service has nowhere to put a tile. Nothing else separates them — same code, same database, same port.

A

As a package — tile and menu icon

Build it on any machine that has Python 3, including the NAS itself. There is nothing to compile.

git clone https://github.com/MARVion123/dupfinder.git
cd dupfinder
python3 install/spk/build_spk.py
# -> install/spk/dist/dupfinder-<version>.spk

In DSM, set Package Center → Settings → Trust Level to Any publisher, then upload the file under Manual Install. Or do it over SSH, which prints what DSM actually says instead of "failed to install":

sudo sh install/spk/install-spk.sh \
    install/spk/dist/dupfinder-*.spk

Then grant it access to what you want scanned: Control Panel → Shared Folder → Edit → Permissions → System internal user → dupfinder. A scan silently skips what it cannot read, and deleting fails on what it cannot write.

B

As a service — sees everything, no tile

Over SSH as root. Starts with the NAS and reaches every share without granting anything.

# fetch and roll out
mkdir -p /volume1/dupfinder/src
git clone https://github.com/MARVion123/dupfinder.git \
    /volume1/dupfinder/src/dupfinder
chmod +x /volume1/dupfinder/src/dupfinder/install/deploy.sh
/volume1/dupfinder/src/dupfinder/install/deploy.sh --force

# then, in a browser
http://<nas-ip>:8777
C

Keeping it current

The same script pulls changes. It leaves the service alone when nothing moved, runs compileall over the new checkout before stopping anything, and puts the previous copy back if the new one does not answer within 15 seconds.

deploy.sh            # deploy if the remote moved
deploy.sh --check    # show what would happen, change nothing

# or nightly, on a timer
systemctl enable dupfinder-deploy.timer
systemctl start  dupfinder-deploy.timer
D

Container

Mount every volume you want to scan at the same path inside the container — otherwise the paths in the UI will not match the paths on the NAS.

docker compose -f install/docker-compose.yml up -d
E

Try it without installing anything

On any machine with Python 3.8 or newer.

python3 -m dupfinder serve --port 8777
python3 -m dupfinder scan /path/to/folder   # headless
python3 -m dupfinder report --top 25
Requirements

Python 3.8+, and nothing else

Pillow is optional and unlocks image previews, EXIF details and the perceptual hash. An Anthropic API key is optional and unlocks AI suggestions — without one, a local rule engine fills the same column.

Safety

The root allowlist is the boundary

Only paths below the configured roots can be browsed, scanned or deleted — every filesystem call goes through that check. Set an access token if the port is reachable beyond your own network.

If an install fails

Clear the wreckage before retrying

A half-failed DSM install leaves the system contradicting itself: synopkg list shows the package while synopkg status answers non_installed. Every later attempt then fails too, because DSM believes it is already there. install-spk.sh --clean removes the leftovers and keeps your database.

Keeping an existing database

Point the package at it

Moving from the service to the package does not have to cost you a scan. Write the old path into a file and the package uses it:

echo /volume1/dupfinder/data \
  > /var/packages/dupfinder/var/datadir
§ 07

What it cannot do

So you do not have to find out for yourself.

Limit

No similarity for Office files

.docx, .xlsx and .odt are ZIP containers. Two revisions of the same report look like strangers at the byte level. Exact duplicates are still found.

Limit

No re-encoded video

The same film in two encodings is not recognised as similar. The same film in two containers is.

Limit

The DSM package is experimental

An .spk can be built, but it failed reproducibly in Package Center on a DSM 7.2 box. The systemd route above is the one that holds up.

Limit

A tool for one person

No user management, no roles, no multi-user operation. It is meant as an admin tool on your own network, not as a service for many.

§ 09

The badges, written out

Four words at the top of this page are claims. Here is what each one actually means, and how you can check it.

Runs on your hardware

The tool is a single Python process on your NAS. It opens a port on your own network and waits for you to open a browser. Your files are read, hashed and compared where they already sit — the bytes never leave the machine.

That is checkable, not just asserted: the application code contains no outbound address at all. There are exactly two networking imports in the whole program, both in server.py, and both for the inbound direction — http.server and urllib.parse. No telemetry, no crash reports, no ping to an update server.

The one connection that ever goes out is the AI suggestion pass. It goes to Anthropic, and the library that makes it is imported inside the function that requires a configured key — with no key it is never even loaded. What travels is paths, sizes and timestamps, never file contents.

No cloud, no account

No sign-up, no subscription, no licence key, no activation. There is no vendor service that can go down, change its pricing or be switched off one day — because there is no vendor service. What you installed keeps working even if this repository disappears tomorrow.

The flip side: there is no user management either. Whoever can reach the port can do everything. On a home network behind a router that is the usual shape for an admin tool; if the port needs to be reachable beyond that, set an access token (auth_token). Every request then has to carry it in the Authorization header.

Python standard library

The scanner uses nothing that does not already ship with Python: hashlib for hashing, sqlite3 for storage, http.server for the interface, os.scandir for walking the tree. No web framework, no ORM, no compiled extensions.

That sounds like a matter of taste; it is a practical one. Building wheels on a NAS CPU is tedious, the compiler is often missing, and pip is not a given on DSM. A tool with no dependencies is installed by copying it.

There are two extras, both optional, both degrading quietly when absent: Pillow for image previews, EXIF details and the perceptual hash, and the anthropic package for AI suggestions. Without Pillow, images fall back to the slower content hash; without a key, a local rule engine fills the same column.

Synology DSM 7

Built and run on DSM 7. What it actually requires, though, is only a Linux with Python 3.8 or newer — the DSM parts are conveniences, not dependencies:

  • The exclusion list knows @eaDir, #recycle, #snapshot, @sharesnap and the rest of Synology's special folders. Without them a scan reports thousands of meaningless "duplicates" out of the thumbnail index.
  • The DSM recycle bin is offered as a deletion target, next to quarantine and permanent removal.
  • The default roots are /volume1 through /volume4, /volumeUSB1 and /var/services/homes.
  • Hardlinks are collapsed, so the tool never promises you space that does not exist.

On an ordinary Linux box, in a container or on macOS it runs just the same; you simply set the roots yourself.

Python 3.8 or newer

3.8 is what DSM 7 ships, which is where the floor comes from. Newer versions are noticeably faster exactly where it hurts: the similarity pass is a tight loop over individual bytes, and loops like that gained a lot in Python 3.11.

If a newer Python is available as a package on your NAS, the switch is worth making. A virtualenv on the data volume survives DSM updates too: 

/usr/local/bin/python3.11 -m venv /volume1/apps/venv
/volume1/apps/venv/bin/pip install Pillow

# then point the unit file at it
ExecStart=/volume1/apps/venv/bin/python -m dupfinder serve --port 8777

The deploy script reads the interpreter out of the unit file, so a switch like this needs no follow-up anywhere else.
